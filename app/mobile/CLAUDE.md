# Mobile (Expo / React Native, TypeScript strict)

## Running

```bash
npm start
```

API base URL comes from `EXPO_PUBLIC_API_URL` (fallback in `src/config/constants.tsx` is a LAN IP for a physical device). Prefer setting the env var over editing the fallback. Typecheck with `npx tsc --noEmit`; no tests or linter are configured.

## Structure (`src/`)

- `api/` — one file per backend resource, built on `apiClient` (`client.ts`). Errors are thrown as `Error(responseText)`; use `errorMessage(e, fallback)` from `client.ts` to show FastAPI's `detail`.
- `api/cache.ts` — read-through AsyncStorage cache (`cached(key, fetcher, forceRefresh)`), no TTL. All keys go through `cacheKey()` (prefix `cache:`) so `logout` can wipe them with `clearCache()`. Mutations must write the updated object back to every cached copy (see `storeWardrobe` in `wardrobes.ts`), or lists go stale.
- `context/AuthContext.tsx` — token + current user, persisted in AsyncStorage (`auth:token`, `auth:user`). `isLoading` only covers the startup hydrate: `RootNavigation` swaps the whole tree for a spinner while it's true, so don't toggle it in `login`. Use `setUser` to update the current user (it persists too). Any 401 from `apiClient` calls `logout` (handler registered via `setUnauthorizedHandler`), so an expired token sends the user back to login.
- `context/ThemeContext.tsx` + `theme/colors.ts` — light/dark `ThemeColors`. Never hardcode colors; read them from `useTheme().colors`.
- `styles/<feature>.ts` — `createXStyles(colors)` factories, used as `useMemo(() => createXStyles(colors), [colors])`. Put styles here, not inline.
- `navigation/` — `RootNavigation` (auth vs app), bottom tabs in `AppNavigator`, one stack per tab when it needs one (`WardrobeNavigator`). Stacks export their `ParamList`; screens type props with `NativeStackScreenProps<ParamList, "Route">`.
- `components/ui/Chip.tsx` — the one pill used for filters/pickers (selected = filled). Don't hand-roll chip styles.
- `utils/confirm.ts` — `confirmDestructive(title, msg, confirmText)` for deletes/leave. Use it instead of `Alert.alert` with buttons: react-native-web ignores those buttons, so confirms silently never fire on web.
- Wardrobe stack: list → `WardrobeDetail` → `ItemForm` (edit for the item owner, read-only for other members; `canRemove` shows "Remove from this wardrobe") / `AddExistingItems`. Pushed screens show a themed header with only a back button, so their `SafeAreaView` uses `edges={["bottom","left","right"]}` (no double top inset).
- `Wardrobe.item_count` is client-only: filled from the list's `item_counts`, and refreshed by the detail screen (`storeWardrobe`) when it loads items. `storeWardrobe` merges, so it keeps client-only fields.
- Item photos: `api/images.ts` `uploadImage(token, uri, width)` shrinks to 1600px JPEG (`expo-image-manipulator`), asks the API for a presigned POST and uploads straight to storage, returning the `image_asset_id` to send with the item. `ItemFormScreen` uploads right after picking (library, plus camera on native), and Save waits for it. It shows a photo tip (tops on a hanger against a plain wall, trousers flat): the 3D renderer reads colour, pattern and prints from that photo. Show images with `expo-image` and `cacheKey: image_asset_id`: the signed URL changes on every fetch. URLs expire after 24h; `WardrobeDetailScreen` refetches once when an image fails to load.
- Outfits tab: `OutfitsNavigator` → `OutfitsList` (filter All / Personal / per wardrobe) → `OutfitDetail` → `OutfitForm` (pick wardrobe for new outfits, toggle items, live preview). `components/outfit/OutfitCanvas.tsx` is the single transform → style renderer (free canvas: `translate` = item center in 0..1, size = 40% × `scale`, z_index order; dressed outfits: see below). New items get positions from `utils/outfitLayout.ts` (`defaultLayout`, by category).
- The outfit form fetches wardrobes with `forceRefresh` (roles may have changed elsewhere). Deleting or removing an item drops the outfits cache (`dropCache`), because the backend pulls it out of outfits.
- Layering meta: `api/meta.ts` (`useLayering()`, `subcategoryLabel()`) loads `GET /meta/layering` once (cached). Item form shows "Type" chips filtered by the chosen categories; cards show the type label.
- Bodies (plan 12): `api/bodies.ts` (`getBodies`, cached; default mannequin is a device setting in AsyncStorage `settings:default_body`). `components/body/BodyCanvas.tsx` draws a pose at its aspect ratio with `cacheKey: image_key` and an optional keypoint overlay; children are drawn on top (used by Profile; outfits draw with Skia, see below). `onImageError` refetches with `forceRefresh` (expired URL or re-seeded image). Profile has the Mannequin card (`MannequinSection`, keypoints toggle only in `__DEV__`).
- Dressed outfits (plan 13/14): `OutfitCanvas` with `bodyId` renders `DressedCanvas`, a **Skia** canvas: mannequin pose image + every garment as a textured `Vertices` mesh (`GarmentMesh`, `plain_url` = no glow); without a body, the old free canvas. Garments are placed on the **neutral** pose (`utils/fit.ts`) and then skinned onto the shown pose (`utils/skin.ts`); neutral goes through the same skinning, which is what brings sleeves onto the arms.
- `utils/skin.ts` (plan 14): per garment a "garment pose" = neutral skeleton with virtual arms along its sleeves (`shoulder_*`→`sleeve_*` anchors) and legs along its trouser legs (`hem_*`). A 16×16 grid is bound to bones by capsule distance (torso radius = half chest/hip width, `LIMB_BIAS` favours the torso); for tops with a known torso column only the torso moves the cloth inside it, the sleeve of that side outside it (ramped). Each bone moves rigidly to the target pose; triangles are sorted so limbs draw over the torso. Skirts and accessories are rigid (one bone: head, forearm, shin per shoe, ...). `utils/fit.ts` is pure: `drawOrder`/`zOf` (port of `common/layering.py`, keep them in sync), `fitRects` (anchors + body keypoints → rects; tops scale by length via `LENGTH` levels waist..ankle, width = the torso column (between the sleeve shoulders) → chest × `EASE` × role padding, or length / 1.38 × padding when no sleeves were found; bottoms by waistband + hem; shoes/accessories by keypoint boxes; a single shoe is drawn on both feet, mirrored), `placeItem` (+ `fit_adjust`), `dragToAdjust`, `outfitWarnings`. Tune the numbers there.
- Editing: the outfit form passes `selectedId/onSelect/onAdjust/onInteract` to the canvas. One `PanResponder` on an overlay does tap-to-select (hit test, topmost first) and drag (live, committed on release). It doesn't let the parent ScrollView take the gesture while something is selected; `onInteract` disables the ScrollView during a drag. Scale/rotate/reset are buttons in `LayersPanel` (works on web and phone without gesture-handler). `LayersPanel` lists layers top first: tuck / into-shoes chips, up/down within the same band (`layer_offset`), eye toggle, warnings.
- 3D renders (plan 19): read-only `OutfitCanvas` (cards, detail) shows `render_url` (server Blender render, same framing) when there is one, else the Skia view; a "Rendering 3D…" badge while `render.status === "queued"`. Detail polls `getOutfit` every 4 s and the list refreshes every 5 s while something is queued. The editor always uses the live Skia view.
- Pose picker (plan 14): chips under Mannequin in the outfit form, from the body's `poses`; saved as `pose_id`. Tweaks (`fit_adjust`) live in the neutral placement, so they carry across poses and bodies.
- Skia on web: `index.ts` awaits `loadSkia()` before requiring `App`. `src/loadSkia.web.ts` loads CanvasKit (`LoadSkiaWeb`, wasm from jsDelivr matching `canvaskit-wasm`'s version; the first web load takes a few seconds, 8 MB); `src/loadSkia.ts` is the native no-op (Skia is in Expo Go). Keep web-only imports in `.web.ts` files: Metro bundles every `require` regardless of `Platform.OS` checks, and CanvasKit's JS requires `fs` (red screen on the phone). Check a native bundle with `npx expo export --platform ios`.
- Cache keys are versioned (`VERSION` in `api/cache.ts`, now `v5`): bump it when cached API data changes shape or gets backfilled server-side; `purgeOldCache()` drops old entries on startup.
- `types/` — API shapes. The backend sends `_id`; users go through `normalizeUser` (in `api/users.ts`) so app code uses `user.id`. Wardrobes keep `_id`.

## E2E testing (Expo web, no phone needed)

1. Web deps without touching `package.json`: `npm install --no-save react-dom@<react version> react-native-web@0.21`. Any later `npm install`/`npx expo install` removes them: install them again.
2. An isolated API: a small launcher that imports `app.backend.api.src.main:app`, overrides `get_db` with a `mongomock` DB (patch `Cursor.to_list`), adds `CORSMiddleware(allow_origins=["*"])`, seeds users via `services.user.create_user`, and runs uvicorn on 8001. Never point E2E at the real DB.
3. `EXPO_PUBLIC_API_URL=http://localhost:8001 npx expo start --web --port 8090`, and drive it in the browser pane. On web, stub `window.confirm` to accept destructive confirms.
Flows that need the real worker (photo → cutout → suggestions) can't run on the mongomock API: the worker reads Atlas. Run Expo web against the real local API instead (port 8091, **no `EXPO_PUBLIC_API_URL` override**: `app/mobile/.env`'s LAN URL works in the browser too; `CORS_ORIGINS` set in `app/infra/compose/.env`) and use the `admin@test.io` test account. Clean up only what you created, through the app.

4. Photos: point the launcher's S3 env at the compose SeaweedFS (`S3_ENDPOINT_URL=http://localhost:8333`, dev keys) **with `S3_BUCKET=dress-me-up-test`**. The real stack uses `dress-me-up` in the same SeaweedFS, so never bulk-delete there (a test cleanup once deleted a real item photo). expo-image-picker's web picker opens its `<input type=file>` with `dispatchEvent(new MouseEvent("click"))`, so stub the OS dialog with a capturing `click` listener on `document` that sets `input.files` (a canvas-generated `File`) and dispatches `change`. Patching `HTMLInputElement.prototype.click` doesn't work.

## Gotchas

- All Expo dev servers started from `app/mobile` share Metro's transform cache, `EXPO_PUBLIC_*` values included. A web server started with another `EXPO_PUBLIC_API_URL` (e.g. `localhost` for the mongomock API) leaks it into the phone's bundle: the phone then calls `localhost` = itself ("Could not connect to the server"). Don't run such a server next to the phone's, and restart the phone's with `npx expo start -c` after using one.

- Browser pane: the `zoom` action can return a stale frame of a Skia canvas; take a fresh `screenshot` to judge rendering.
- Don't put `flex: 1` in a `FlatList`/`ScrollView` `contentContainerStyle`: it stops the list from scrolling. Use `listContent` / `scrollContent`, and `flexGrow: 1` for empty states.
- File uploads on native: Expo's `fetch` (SDK 52+) throws `Unsupported FormDataPart implementation` for React Native-style `{uri, name, type}` FormData parts. Append `new File(uri)` from `expo-file-system` (it implements `Blob`); on web, append a real `Blob`. See `api/images.ts`.
- Lists read from cache on focus (`useFocusEffect`), and pull-to-refresh passes `forceRefresh`.
